# 原型转设计说明书转换铁律 (Demo-to-Spec Mechanical Compiler Law)

## 1. 角色定位：零设计思想的纯机械语法编译器
- 在执行任何原型（HTML/Tailwind/Alpine）转设计说明书（Specification）或迁移到内部平台任务时，AI **唯一且严格的定位是【机械语法编译器】**。
- **绝对禁止带有任何主观设计思想！绝对禁止任何需求和体验层面的自作主张、优化、美化或自由发挥！**
- **绝对禁止发明任何未在源 HTML 中出现的内容**：严禁自创指标卡、虚构百分比走势、自编打分规则、随意画线框图、添加 emoji、臆造重置/导出按钮等。

## 2. 物理真值基准优先铁律 (Ground-Truth First)
- 转换必须是确定性的。转换前必须以源 HTML 的物理 DOM 为唯一基准（可使用 `SKillS/skill-demo-to-spec/scripts/extract_demo_dom.py` 提取）。
- **字面量 100% 物理镜像**：
  1. 页面标题与顶层 Tab 页签名称：100% 逐字对应。
  2. 容器栅格与区域标题：源 HTML 采用什么栅格（如 30%-40%-30% 三列），说明书及线框图必须精确体现该栅格，严禁擅自压平或篡改。
  3. 表格结构：源 HTML 的 `<th>` 表头列数与列名必须 100% 镜像，原页面是 10 列就必须写 10 列，严禁擅自删减。
  4. 筛选控件：placeholder 占位符、下拉选项必须 100% 逐字对应。
  5. 状态徽标：枚举值（如“差”、“一般”、“正常”）必须与源 HTML 逐字对应，严禁自创状态。

## 3. 唯一的转换职责：技术栈规范映射
- 转换的唯一任务，是将手写 HTML 原生元素机械转译为内部平台规范：
  - 手写下拉 ➔ `<IxSelect>`
  - 手写表格 ➔ `<IxTable>` (列配置与源 HTML 表头一一对应)
  - 状态标签 ➔ `<IxTag>`
  - 侧拉抽屉 ➔ `<IxDrawer>`
- 输出的高保真说明书与纯净 Mock/Types 物料，必须确保内部研发团队能够 1:1 像素级精准还原原 Demo。

## 4. 强制执行：输出时示意图与 Demo 样式布局一致性检视门禁 (Visual Layout Verification)
- **每个 spec 说明书输出时，必须强制执行一轮结构示意图与原 Demo 页面样式布局的专项检视**：
  1. **空间骨架与容器划分检视**：Header、主内容区、分栏比例（如 30%:40%:30% 或 50%:50%）是否与源 Demo 页面完全一致；
  2. **组件与控件空间位置检视**：操作按钮是在左侧还是右侧、筛选控件的排列次序、搜索框位置是否与源 Demo 一致；
  3. **微观排版与视觉层级检视**：指标数字与等级分布的排布形式（如 2×2 排布、横向分段进度条、30px 纵向列表条）是否 1:1 还原源 Demo；
  4. **表格展示规范检视**：表头列顺序、列对齐方式（数值右对齐、操作居中对齐）、状态标签颜色是否严格一致；
  5. **抽屉与弹窗排版检视**：抽屉宽度（如 640px / 520px）、表单左右排版是否与源 Demo 一致。
- 若检视发现任何示意图与原 Demo 布局存在差异，必须立即修正示意图代码，直至完全一致方可交付。

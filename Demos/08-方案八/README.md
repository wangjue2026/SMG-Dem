# 08-方案八

本目录用于存放和维护**方案八（迭代一拆解版）**的 Demo 演示页面与相关文件。
源副本来自 `Demos/07-方案七/` 定稿全量版本，在此副本上单独裁剪迭代一范围，**方案七原文保持不变**。

## 目录与文件规范
1. **标识与路径**：
   - **方案八** 路径：`Demos/08-方案八/`
2. **文件结构**：
   - `DEM-首页.html`：首页与全貌监控/指标下钻（已同步自 06-方案六 最新首页，含 AI 巡检条、巡检报告抽屉、体验预警摘要等）
   - `DEM-用户详情.html`：用户排障定位与画像详情
   - `DEM-应用详情.html`：应用详情与关联分析（独立重构演进版）
   - `DEM-体验预警.html`：体验预警页面
   - `DEM-监控配置.html`：监控配置页面
   - `_shell/`：方案八独立的双底座框架（`shell.js` / `shell.css`）

## 二次修订记录（首页字段与口径）

1. 「体验异常对象集中位置」三档改为 **同归属地 / 同接入POP / 同链路**；i 提示同步更新，同链路指**在当前时间范围内，探测分支 / 用户访问不同业务时识别到的体验差的链路**；条目标签宽度 52 → 68px。条目数值展示为「N 人 | N 分支」（文字色 #3D3D3D），**人数与分支数可分别点击**：点人数只筛用户清单并切到用户 tab，点分支数只筛分支清单并切到分支 tab；整行点击仍为两个清单同筛；再次点击同一数字取消。筛选后条件会**回填到对应工具栏筛选器**（同归属地 → IP 归属地、同接入POP → 接入POP、同链路 → 体验差的链路），取消筛选时同步移除回填项；**反向同样联动**——在工具栏删除 Tag / 全部清除时，集中位置的筛选状态、条目高亮与副标题一并复位（以工具栏条件是否仍存在为激活判定）。工具栏下拉选项改为「固定项 + 数据出现的值 + 当前已选」动态合并。
2. 分支 / 用户表「链路」列改为「体验差的链路」，只取体验为差的链路（首条 + 其余 `+N`），无差链路显示 `-`；工具栏链路筛选的选项集合同步为差链路。
3. 用户表「最近使用终端 / IP 归属地 / 最近接入 POP」支持多值：默认展示最高频项，其余以 `+N` 收起，悬浮按使用频次降序列出全部取值并标注前三项为「高频」。示例多值行：`14810（郝星伍）`、`63728（王浩）`。
4. 分支 / 用户表「访问应用数」字段改为「探测应用数」（数值口径不变，仅改名）。
5. 应用表「受损/活跃用户」「受损/活跃分支」改为「体验差的用户」「体验差的分支」，去掉活跃数，只保留体验差的数量；两列表头与数值均右对齐。
6. 列序调整：用户表为 访问体验 → 体验差的链路 → 体验差的应用 → 探测应用数；分支表为 …主要接入POP → 体验差的链路 → 体验差的应用 → 探测应用数。
7. 三张表内「体验差的应用 / 体验差的用户 / 体验差的分支」的数字均可悬浮查看具体对象清单，超过 8 个以「等 N 个」收尾；应用侧对象清单由 `degradedUserNames` / `degradedBranchNames` 提供，数量与表格数字严格一致。
8. 表格内的悬浮信息统一改为**自定义即时浮层**（`hoverTip` + `x-teleport` 到 body 的 fixed 浮层），不再使用浏览器原生 `title`（原生提示有 1s 以上延迟且不可控）；覆盖体验差应用/用户/分支、体验差的链路、最近使用终端、IP 归属地、最近接入 POP、所属组织架构。浮层深色 `#1F2733`、11px、逐行展示，靠近视口右侧/底部时自动翻转位置，不阻塞鼠标事件。

## 第三次修订记录（用户详情，全剧本）

1. **左侧应用监测列表改为全量平铺**：多终端场景不再以终端作为分组，也不再提供分组收起/展开；点击应用后右侧看板自动切到该应用体验最差的探测端（无异常取首个探测端）。
2. **多端端到端探测随终端切换**：当前切片存在多端并发探测时，端到端时延/丢包标块从「访问链路」标题右侧移到多端切换胶囊栏右侧，且只显示当前选中终端的探测结果，切换终端即同步刷新（口径：该端第一公里 + 共享传输/应用段累加）；单探测端场景仍保留标题右侧标块。
3. **多余文案删除**：体验时间线副标题去掉「每 1 分钟探测一次」；访问链路标题去掉应用名，仅保留「（联动时刻 xx:xx）」；去掉多端胶囊栏右侧「当前时段双端并发访问…」说明；去掉「连接器-应用段 / 代理网关-应用段」的段结论文案（仅保留时延 / 丢包率 / 抖动指标卡）。
4. **应用节点取消展开**：链路明细中所有应用节点不再提供展开内容与折叠箭头，「查看应用详情 >」常驻入口同步移除；鼠标悬浮整行提示「点击查看应用详情」，点击或点击拓扑图中的应用节点均在新浏览器标签页打开应用详情页（总部AF 等网关节点保持原有的可展开能力）。

## 第四次修订记录（用户/分支详情，全剧本）

1. **节点悬浮不再展示健康状态**：终端、分支AF、连接器、代理网关、单 POP 节点的悬浮浮层只保留对象名称（分支AF 保留 IP），不再显示「正常/异常」；全球加速骨干网上下车点维持原样。
2. **顶部去掉对象类型标签**：「访问用户 / VIP用户 / 分支机构」标签移除，名称行只保留姓名/分支名。
3. **新增 AI 整体体验分析入口**：访问体验定性标右侧新增「AI 分析」胶囊入口（蓝→青→绿线性渐变描边双星标 + 渐变文字，渐变定义在 body 顶层单份，避免模板克隆后重复 id 失效），点击打开 720px 的「AI ops」对话抽屉，自动填入并发送「请帮我分析XXX的访问体验质量」；抽屉内先跑 6 步分析过程（读取探测数据 → 聚合劣化时段 → 比对应用体验分布 → 定位异常分段 → 核对同 POP/运营商对象 → 汇总责任域与建议时刻，每步约 380ms，带「正在思考」与逐步打勾），约 2.7s 后输出「结论 + 问题时段 / 涉及应用 / 异常分段 / 责任域 / 影响范围 / 建议查看的时段」的对象维度整体解读（非单应用单链路视角）。结论行 14px 加粗，「异常分段」及其段名用异常红。
4. **「建议查看的时段」可直接改写顶部筛选**：输出为劣化区间（如 20:00~20:30）而非时间点，点击后顶部时间筛选切换为「自定义」并写为该时段（`2026-06-04 20:00:00 至 2026-06-04 20:30:00`），同时时间线联动定位到该区间内的最差点并关闭抽屉。
5. **对话抽屉只读**：底部不提供输入框，仅提示「当前仅支持触发式分析，暂不支持自由输入」，并保留「重新分析」触发（重新跑一遍分析过程）。
6. **抽屉细节调整**：标题改为「AIOps助手」；「影响范围」的个体/群体判断改为 tag 展示（个体问题橙、群体问题红、暂无法判断灰、未见扩散绿）+ 说明文字。
7. **链路 AI 诊断解读增加分析过程**：进入对象（默认定位到第一个应用的最新异常点）、切换应用、切换时间点、切换探测端时，AI 诊断解读卡片先进入分析态——顶栏 2s 进度条 + 「AI 正在解读 xx:xx 时刻的链路数据」三点动效 + 三步推理（聚合链路分段指标 / 比对健康基线定位异常段 / 生成诊断结论与建议）+ 骨架屏，约 2s 后切换为结论态；顶栏新增「重新分析」可手动重跑。
8. **AI 诊断解读摘要改为分条目**：顶栏不再放责任域/影响性质标签，改为结论行（`xx:xx 内链路体验差，端到端时延 X / 丢包 Y`，前置状态色竖条）+ 三条灰底标签条目：异常位置 / 责任域 / 影响范围（影响范围 = 已有扩散比例 + 影响性质）；三个标签统一 60px 定宽居中，右侧文字左对齐。
9. **「第一公里」口径纠正**：第一公里指终端/AF 到上车点 POP 的链路，不再写成「局域网网关」；酒店 Wi-Fi 剧本的异常位置改为「客户端 → 马尼拉POP（第一公里）」，相关摘要、判定依据、同链路口径与建议同步改写。
5. **口径**：涉及应用只统计体验为差的应用；异常分段按涉及应用个数降序并列出受影响应用清单；问题时段、责任域、影响范围均取自页面现有探测点、链路明细与剧本既有描述，缺失时显式标注「暂无法判断」，不新增杜撰数据；单 POP 名称解析同时修复 `POP（香港）` 被误显示为「POP北京」的遗留问题。
